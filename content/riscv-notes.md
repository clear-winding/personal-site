## 0. 一句话总览

这门课研究的是: 一台计算机如何从“指令集这个软硬件接口”出发, 组织数据表示、运算器、存储器、总线、I/O 和 CPU 控制, 让程序正确且高效地运行。

复习主线:

```text
系统结构/组成/实现
-> 数据怎么表示
-> 指令怎么设计
-> 运算怎么做
-> 存储怎么分层
-> I/O 怎么接入
-> CPU 怎么取指、译码、执行、控制和流水
```

## 1. 计算机系统概论

### 1.1 存储程序思想

存储程序思想的核心:

- 计算机由运算器、控制器、存储器、输入设备、输出设备组成。
- 指令和数据都用二进制表示。
- 程序和原始数据先存入存储器, 计算机按程序自动执行。

这就是冯·诺依曼型计算机的基础。

### 1.2 计算机系统的层次结构

计算机系统可以看成多级机器:

- 数字逻辑级
- 微程序机器级
- 传统机器级, 即指令集 ISA
- 操作系统机器级
- 汇编语言机器级
- 高级语言机器级
- 应用语言机器级

越往上越接近程序员和应用, 越往下越接近硬件电路。虚拟机器是用软件或以软件为主实现的机器。

### 1.3 系统结构、组成、实现

这三个概念很容易混:

- 计算机系统结构 architecture: 程序员可见的属性, 主要是 ISA 及相关机器级特性。比如指令系统、数据表示、寻址方式、寄存器组织、中断、I/O 结构。
- 计算机组成 organization: 如何在逻辑上实现系统结构。比如数据通路宽度、控制方式、是否有 cache、功能部件如何连接。
- 计算机实现 implementation: 物理实现。比如器件工艺、芯片布局、电路速度、封装。

例子:

- “是否有乘法指令”属于系统结构。
- “乘法指令用专用乘法器还是移位加法实现”属于组成。
- “乘法器用什么工艺制造”属于实现。

### 1.4 透明性、兼容性、系列机

透明性: 某种真实存在的细节, 从某个层次看不到。比如 cache 对普通应用程序员透明。

软件兼容: 一个机器上的软件能在另一个机器上运行。若两台机器 ISA 相同但组成不同, 程序可运行, 但性能可能不同。

系列机: 具有相同或相近系统结构的一系列机器, 可用不同组成和实现满足不同性能/价格需求。

### 1.5 设计方法

三种设计思路:

- 自上而下: 从应用需求出发向下设计, 性能可能好, 但专用性强、周期长。
- 自下而上: 从器件和硬件能力出发向上构造, 易造成软硬脱节。
- 中间开始: 从软硬件接口 ISA 出发, 同时考虑软件和硬件, 是现代设计常用思路。

### 1.6 Amdahl 定律

Amdahl 定律说明: 只优化系统的一部分, 总体加速受该部分占比限制。

设:

- `Fe`: 可改进部分占原总执行时间的比例。
- `Se`: 可改进部分自身加速比。

系统加速比:

```text
Sn = 1 / ((1 - Fe) + Fe / Se)
```

极限:

```text
Sn <= 1 / (1 - Fe)
```

直觉: 优化要抓“大概率事件”。占总时间很少的部分, 即使变得无限快, 总体收益也有限。

### 1.7 CPU 性能公式

常用公式:

```text
CPU time = Instruction Count * CPI * Clock Cycle Time
CPU time = Instruction Count * CPI / Clock Rate
```

想提升性能可以:

- 减少指令数。
- 降低 CPI。
- 提高时钟频率。

但三者会互相影响。比如复杂指令可能减少指令数, 但增加 CPI 或降低频率。

### 1.8 并行性与 Flynn 分类

并行性包含:

- 同时性: 同一时刻发生。
- 并发性: 同一时间段内发生。

Flynn 分类:

- SISD: 单指令流单数据流, 传统单处理器。
- SIMD: 单指令流多数据流, 向量/阵列处理。
- MISD: 多指令流单数据流, 现实中较少。
- MIMD: 多指令流多数据流, 多处理机/多计算机系统。

并行开发途径:

- 时间重叠: 流水线。
- 资源重复: 多个功能部件或多个处理单元。
- 资源共享: 多处理机共享存储/I/O。

## 2. 数据表示

### 2.1 定点数

常见带符号整数表示:

- 原码: 符号位加数值位, 直观但有 +0/-0。
- 反码: 正数同原码, 负数数值位取反, 也有 +0/-0。
- 补码: 正数同原码, 负数为反码加 1, 只有一个 0, 加减法统一。
- 移码: 真值加偏置, 常用于阶码比较。

补码范围:

```text
n 位补码范围: -2^(n-1) 到 2^(n-1)-1
```

8 位补码范围是 -128 到 127。

### 2.2 溢出判断

补码加法中, 两个同号数相加得到异号结果, 发生溢出。

也可用进位判断:

```text
最高位进位 Cn 与次高位进位 Cn-1 不同则溢出
```

### 2.3 浮点数

浮点数表示:

```text
(-1)^S * M * R^E
```

IEEE 754 单精度 32 bit:

- 1 位符号 S
- 8 位阶码 E, 偏置 127
- 23 位尾数字段 fraction

规格化数:

```text
value = (-1)^S * 1.fraction * 2^(E - 127)
```

双精度 64 bit:

- 1 位符号
- 11 位阶码, 偏置 1023
- 52 位尾数

### 2.4 字符与校验

ASCII 常用 7 bit 表示字符。汉字编码涉及输入码、内码、字模码。

奇偶校验:

- 奇校验: 让 1 的个数为奇数。
- 偶校验: 让 1 的个数为偶数。

它只能检测奇数个 bit 错误, 不能纠正。

## 3. 数据运算与运算器

### 3.1 加法器

1 位全加器:

```text
Si = Ai xor Bi xor Ci
Ci+1 = AiBi + (Ai xor Bi)Ci
```

串行加法器:

- 只用一个全加器逐位处理。
- 硬件少, 速度慢。

并行加法器:

- 多个全加器同时处理各位。
- 行波进位 ripple carry 中, 进位逐级传播, 延迟随位数增加。

先行进位 carry lookahead:

```text
Gi = AiBi
Pi = Ai xor Bi
Ci+1 = Gi + PiCi
```

通过并行计算进位减少延迟。

### 3.2 移位

常见移位:

- 逻辑左移/右移: 空位补 0。
- 算术右移: 符号位保持, 用于有符号数除以 2 的近似。
- 循环移位: 移出的位从另一端进入。

### 3.3 乘法

原始二进制乘法类似手算: 看乘数每一位, 若为 1 就加被乘数的移位结果。

Booth 乘法适合补码乘法。它利用相邻位变化来把连续 1 压缩成加/减操作:

- `01`: 加被乘数
- `10`: 减被乘数
- `00` 或 `11`: 不操作

核心好处: 对连续 1 的串减少加法次数。

### 3.4 除法

除法电路常见恢复余数法和加减交替法。补码除法需要处理符号和余数校正。

考试通常不要求完整画复杂电路, 但会问基本过程、移位和加减关系。

### 3.5 运算器 ALU

ALU 支持:

- 算术: 加、减、比较。
- 逻辑: 与、或、非、异或。
- 移位。

CPU 中运算器通常包括 ALU、寄存器、移位器、状态标志和数据通路。

## 4. 指令系统与 RISC-V

### 4.1 ISA 是软硬件接口

指令系统定义机器能直接执行的操作, 是硬件设计者和系统程序员共同看到的界面。

ISA 设计要考虑:

- 操作类型。
- 操作数个数。
- 操作数位置。
- 寻址方式。
- 指令格式。
- 编码方式。
- 对编译器和操作系统的支持。

### 4.2 寻址方式

有效地址 EA 是操作数实际地址。

常见寻址:

- 立即寻址: 操作数在指令中。
- 直接寻址: 地址字段就是 EA。
- 间接寻址: 地址字段指向的内存单元中存 EA。
- 寄存器寻址: 操作数在寄存器。
- 寄存器间接寻址: 寄存器中存 EA。
- 基址/变址寻址: `EA = base + offset` 或 `EA = index + displacement`。
- 相对寻址: `EA = PC + offset`。

考试常考给定寄存器和内存内容计算 EA。

### 4.3 指令格式与操作码编码

指令格式要在以下因素间折中:

- 操作码位数。
- 地址码位数。
- 指令长度。
- 寻址灵活性。
- 硬件译码复杂度。

扩展操作码:

- 高频指令用短操作码。
- 低频或地址字段少的指令可用较长操作码。
- 目标是减少平均指令长度。

Huffman 编码思想:

- 高频事件用短码, 低频事件用长码。
- 用于指令编码时可降低平均长度, 但可能增加译码复杂度。

### 4.4 RISC 与 CISC

CISC:

- 指令复杂, 格式多样。
- 一条指令可完成较复杂操作。
- 可能减少指令数, 但硬件和译码复杂。

RISC:

- 指令简单、规整。
- load/store 架构, 算术逻辑操作主要在寄存器之间进行。
- 固定或少数几种指令格式。
- 寄存器多, 便于流水线。
- 编译器承担更多优化责任。

RISC 关键技术:

- 大量通用寄存器。
- load/store。
- 简单寻址方式。
- 规整指令格式。
- 流水线友好。
- 编译优化支持。

### 4.5 RISC-V 基础

RISC-V 是开放 ISA。常见基础整数指令集:

- RV32I: 32 位整数基础指令集。
- RV64I: 64 位整数基础指令集。

寄存器:

- 32 个通用寄存器 `x0` 到 `x31`。
- `x0` 恒为 0。

常见格式:

- R-type: 寄存器-寄存器运算, 如 `add rd, rs1, rs2`。
- I-type: 立即数、load、jalr, 如 `addi`, `lw`。
- S-type: store, 如 `sw rs2, imm(rs1)`。
- B-type: 条件分支, 如 `beq`, `bne`。
- U-type: 高位立即数, 如 `lui`, `auipc`。
- J-type: 跳转, 如 `jal`。

load/store 例子:

```text
lw  x5, 0(x6)    # x5 = Mem[x6 + 0]
sw  x5, 4(x6)    # Mem[x6 + 4] = x5
```

分支通常使用 PC 相对偏移。

## 5. 总线与输入输出系统

### 5.1 I/O 系统组成

I/O 系统包括:

- 外部设备。
- 设备控制器。
- 总线。
- I/O 软件和中断/DMA 等控制机制。

I/O 的目标是在 CPU、主存和外设之间交换数据。

### 5.2 RAID

RAID 把多个物理磁盘组织成一个逻辑磁盘, 目标是提高性能、容量或可靠性。

常见级别:

- RAID 0: 条带化, 性能高, 无冗余。
- RAID 1: 镜像, 可靠性高, 空间利用率约 50%。
- RAID 5: 分布式奇偶校验, 可容忍一块盘失效。
- RAID 6: 双重校验, 可容忍两块盘失效。

### 5.3 总线

总线是一组共享通信线路, 用于部件之间传送信息。

按功能:

- 数据总线。
- 地址总线。
- 控制总线。

按位置:

- 片内总线。
- 系统总线。
- I/O 总线。

总线性能指标:

- 宽度。
- 时钟频率。
- 带宽。
- 仲裁方式。
- 同步/异步。

总线带宽常用:

```text
带宽 = 总线宽度(bit) * 频率 / 8
```

### 5.4 总线仲裁与时序

多个主设备要使用总线时需要仲裁:

- 集中式仲裁: 一个仲裁器统一决定。
- 分布式仲裁: 各设备共同竞争。

同步总线:

- 由统一时钟控制。
- 简单快速, 但受时钟偏斜和设备速度差异影响。

异步总线:

- 通过握手信号协调。
- 适合速度差异大的设备。

### 5.5 I/O 控制方式

程序查询方式:

- CPU 不断轮询设备状态。
- 简单, 但浪费 CPU。

中断方式:

- 设备准备好后中断 CPU。
- CPU 不必一直等待。

DMA:

- 直接内存访问。
- DMA 控制器在外设和内存之间搬数据。
- CPU 只负责初始化和结束处理。
- 适合大块数据传输。

通道/I/O 处理机:

- 更独立的 I/O 控制能力。
- 减轻 CPU I/O 负担。

## 6. 存储器层次结构

### 6.1 为什么需要层次结构

存储器有三大矛盾:

- 速度。
- 容量。
- 价格。

越快越贵容量越小, 越大越便宜速度越慢。因此用层次结构组合:

```text
寄存器 -> Cache -> 主存 -> 辅存
```

局部性原理:

- 时间局部性: 刚访问过的内容近期可能再访问。
- 空间局部性: 刚访问地址附近的内容近期可能被访问。

### 6.2 命中率、平均访问时间、访问效率

命中率:

```text
H = 命中次数 / 总访问次数
```

平均访问时间:

```text
TA = H*T1 + (1-H)*T2
```

其中 T1 是上层存储器访问时间, T2 是下层访问时间。

访问效率:

```text
e = T1 / TA
```

如果用 `r = T2/T1`, 则:

```text
e = 1 / (H + (1-H)*r)
```

注意: 当 r 很大时, H 必须非常接近 1 才能有高效率。

### 6.3 SRAM、DRAM、ROM

SRAM:

- 触发器存储。
- 快, 贵, 常作 Cache。

DRAM:

- 电容存储。
- 需要刷新。
- 容量大, 便宜, 常作主存。

ROM:

- 只读或主要只读。
- 常用于固件。

### 6.4 Cache 基本结构

Cache 和主存按块划分。访问时:

1. CPU 给出主存地址。
2. Cache 根据地址查找对应块。
3. 命中则直接返回。
4. 未命中则从主存调入包含该字的一整块。

Cache 需要解决:

- 映像: 主存块能放到 Cache 哪些位置。
- 查找: 如何判断是否命中。
- 替换: 满了后换出哪一块。
- 写策略: 写命中/写未命中怎么处理。

### 6.5 Cache 映像方式

全相联:

- 任意主存块可放任意 Cache 块。
- 冲突少, 利用率高。
- 硬件复杂, 需要相联比较。

直接映像:

```text
Cache 块号 = 主存块号 mod Cache 块数
```

- 硬件简单, 速度快。
- 冲突多。

组相联:

```text
Cache 组号 = 主存块号 mod Cache 组数
```

组内任意位置可放。它是全相联与直接映像的折中。

### 6.6 地址划分

直接映像地址通常分为:

```text
Tag | Index | Block Offset
```

组相联:

```text
Tag | Set Index | Block Offset
```

计算步骤:

1. 块内偏移位数 = `log2(块大小 Byte)`。
2. 行/组索引位数 = `log2(Cache 行数或组数)`。
3. Tag 位数 = 地址总位数 - 索引位数 - 偏移位数。

### 6.7 替换与写策略

替换算法:

- FIFO。
- LRU。
- Random。

写策略:

- Write-through 写直达: 同时写 Cache 和主存, 简单但写流量大。
- Write-back 写回: 只写 Cache, 替换时若脏再写回主存, 性能好但控制复杂。

写未命中:

- Write allocate: 调块进 Cache 再写。
- No write allocate: 直接写主存。

### 6.8 虚拟存储器

虚拟存储器用较小主存配合较大辅存, 给程序一个更大的地址空间。

分页:

- 虚拟地址分为虚页号 VPN 和页内偏移。
- 页表把虚页号映射到物理页框号 PPN。
- 页内偏移不变。

TLB:

- 页表项缓存。
- 加速地址转换。

缺页:

- 访问页不在主存时发生。
- 操作系统把页面从磁盘调入主存。

Cache 对多数程序员透明；虚拟存储器通常对应用程序员透明, 但操作系统能看到。

## 7. CPU 与控制器

### 7.1 CPU 基本组成

CPU 包括:

- 运算器 datapath。
- 控制器 control unit。
- 寄存器组。
- 内部总线。

基本指令周期:

1. 取指 IF。
2. 译码 ID。
3. 取操作数。
4. 执行 EX。
5. 访存 MEM。
6. 写回 WB。

不同指令可能只用其中部分阶段。

### 7.2 数据通路

数据通路连接 PC、指令存储器、寄存器堆、ALU、数据存储器、立即数生成器和多路选择器。

对 RISC-V:

- R 型指令: 读两个寄存器, ALU 运算, 写 rd。
- load: 读 rs1, 加立即数得地址, 访存读, 写 rd。
- store: 读 rs1 和 rs2, rs1+立即数得地址, 把 rs2 写内存。
- branch: 读两个寄存器比较, 根据结果更新 PC。

### 7.3 控制器

控制器根据指令操作码和状态信号产生控制信号:

- ALUOp
- RegWrite
- MemRead
- MemWrite
- MemToReg
- ALUSrc
- Branch
- PCSrc

硬布线控制:

- 由组合逻辑直接生成控制信号。
- 速度快。
- 修改困难。

微程序控制:

- 控制信号编码成微指令, 存在控制存储器中。
- 修改和扩展较灵活。
- 速度可能较慢。

### 7.4 微程序控制

微指令包含:

- 微操作控制字段。
- 下地址字段或转移控制字段。

微程序控制器执行过程:

1. 根据机器指令操作码找到微程序入口。
2. 逐条取微指令。
3. 微指令发出控制信号。
4. 根据顺序或条件转移到下一微地址。

水平型微指令:

- 控制位多, 并行性强, 字长长。

垂直型微指令:

- 编码程度高, 字长短, 译码开销大, 并行性弱。

### 7.5 单周期、多周期、流水线

单周期 CPU:

- 每条指令一个时钟周期完成。
- 周期必须按最慢指令设置, 浪费。

多周期 CPU:

- 一条指令分多个短周期完成。
- 不同指令用不同周期数。
- 功能部件可复用。

流水线 CPU:

- 把指令执行分阶段重叠。
- 典型五级: IF, ID, EX, MEM, WB。
- 理想加速比接近流水级数, 但受冒险影响。

### 7.6 流水线冒险

结构冒险:

- 多条指令同一时刻争用同一硬件资源。
- 解决: 增加资源或暂停。

数据冒险:

- 后续指令需要前一指令尚未写回的结果。
- 解决: forwarding/bypassing, stall。

控制冒险:

- 分支跳转导致下一条指令不确定。
- 解决: 分支预测、延迟槽、冲刷流水线。

load-use 冒险:

```text
lw  x1, 0(x2)
add x3, x1, x4
```

即使有转发, 通常也需要停顿 1 个周期, 因为 load 数据到 MEM 末才可用。

### 7.7 流水线性能

理想情况下:

```text
流水线吞吐率提高约为级数 k
```

但真实速度受以下影响:

- 流水级不均衡。
- 寄存器开销。
- 冒险停顿。
- 分支错误预测。
- cache miss。

平均 CPI 可写成:

```text
CPI = 理想 CPI + stall cycles per instruction
```

## 9. 复习建议

这门课的题目常分两类:

- 概念辨析: 结构/组成/实现、RISC/CISC、Cache/虚拟存储、硬布线/微程序。
- 手算设计: Amdahl、CPU time、补码、浮点、EA、Cache 地址字段、平均访问时间、流水线 CPI。

复习时不要只背名词。每个概念都要能回答三个问题:

1. 它解决什么问题？
2. 它怎么做？
3. 它的代价和限制是什么？

能按这三个问题讲清楚, 基本就能应付大多数简答和分析题。
