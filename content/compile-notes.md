## 新资料补充: 期末更容易考的手推题

根据你给的 `编译原理` 文件夹，编译原理最值得补的是“给文法/正规式/代码片段让你手推”的题型。复习时不要只背概念，至少要能在纸上完整走一遍。

- 词法题常把 [正规式](?doc=deep-dive&anchor=compile-regular-expression#reader)、NFA、DFA、最长匹配放在一起考。看到“标识符、数字、关键字”这类描述，要能写正规式，也要知道关键字和标识符冲突时通常用最长匹配加关键字表处理。
- 语法题常让你先改文法，再算 FIRST/FOLLOW，再判断 LL(1)。如果有左递归或左公因子，先改文法，不要直接填表。
- LR 题常考项目集闭包和 goto。点在产生式末尾代表可规约，点后是终结符代表可移进，一个状态里同时想移进和规约就是移进-规约冲突。
- 语义与中间代码题常给表达式、if、while、for，让你写三地址码或四元式。关键是先定标号，再把条件跳转写清楚。
- 优化题常给基本块代码，让你画 DAG、删除公共子表达式、识别活跃变量。注意变量被重新赋值后，旧表达式不能再随便复用。
- 运行时题常问活动记录、参数、返回地址、局部变量、静态链/动态链。递归一定需要每次调用独立保存现场。
- 目标代码题常问寄存器不够怎么办。答案要落到冲突图、图着色、溢出 spilling。

## 0. 一句话总览

编译器做的事情是: 把一种语言写的程序, 在保持语义不变的前提下, 翻译成另一种语言的程序。最常见的是把高级语言翻译成机器码或汇编代码。

你复习时可以把整门课看成一条流水线:

`字符流 -> 词法分析 -> token 流 -> 语法分析 -> 语法树/分析树 -> 语义分析 -> 中间代码 -> 优化 -> 目标代码`

这条线能串起几乎所有考点。

## 1. 编程语言与编译器引论

### 1.1 编程语言分类

按抽象层次看:

- 机器语言: 直接由机器执行, 但难写难读。
- 汇编语言: 用助记符表达机器指令, 需要汇编器。
- 高级语言: 接近人类思维, 需要编译或解释。
- 专用语言: SQL、Matlab、领域脚本等, 为特定问题服务。

按执行方式看:

- 编译型: 先整体翻译成目标程序, 再运行。C/C++ 常被作为例子。
- 解释型: 边读边执行, 常见于脚本语言。
- 混合型: 先编译成字节码或中间表示, 再由虚拟机解释或 JIT 编译。

按类型检查时间看:

- 静态类型: 编译期检查类型, 错误更早暴露。
- 动态类型: 运行期检查类型, 灵活但运行期错误更多。

### 1.2 编译器结构

编译器通常分为前端和后端:

- 前端: 与源语言有关。包括词法分析、语法分析、语义分析、中间代码生成。
- 后端: 与目标机器有关。包括优化、目标代码生成、寄存器分配、指令调度。

中间代码是前后端之间的“接口”。它的意义很大: 前端只要翻译到统一 IR, 后端就能面向不同机器生成代码；同一个优化器也可以复用。

“遍”是 compiler pass, 意思是对程序表示扫描处理一遍。多遍编译器结构清晰, 但可能慢；一遍编译器速度快, 但对前后依赖要求高。

## 2. 词法分析

### 2.1 词法分析器做什么

词法分析器 scanner 从左到右扫描源程序字符流, 识别出一个个单词 token, 并给出属性值。

例如:

```text
sum = a + 10
```

可能被识别成:

```text
id(sum), assign, id(a), plus, num(10)
```

token 是语法分析器真正关心的输入。词法分析不负责理解表达式结构, 只负责“这段字符是什么类别”。

常见 token 类别:

- 关键字: `if`, `while`, `return`
- 标识符: 变量名、函数名
- 常量: 整数、浮点数、字符串
- 运算符: `+`, `*`, `==`, `&&`
- 分界符: `(`, `)`, `{`, `}`, `;`

### 2.2 正规式与正规集

词法规则通常用正规式 regular expression 描述。正规式能表达的语言叫正规语言/正规集。

基本构造:

- `a`: 字符 a
- `ε`: 空串
- `r|s`: 选择
- `rs`: 连接
- `r*`: Kleene 闭包, 重复 0 次或多次

例如标识符可写成:

```text
letter (letter | digit)*
```

它表达: 第一个字符是字母, 后面可以是字母或数字的任意重复。

### 2.3 NFA、DFA 与识别

正规式用于描述规则, 有限自动机用于识别字符串。

- NFA: 非确定有限自动机。一个状态读同一个字符可能有多条边, 还可能有 ε 边。
- DFA: 确定有限自动机。每个状态对每个输入字符最多一个后继。

考试常见流程:

1. 写正规式。
2. 正规式构造 NFA。
3. NFA 用子集构造法转 DFA。
4. DFA 最小化。
5. 用 DFA 扫描源程序。

你可以把 DFA 理解成“带状态的分类器”: 输入一个字符就换一个状态, 走到终态说明识别出某类 token。

### 2.4 词法分析实现

手工实现时常见两种思路:

- 程序中心法: 用条件分支直接写扫描逻辑。
- 数据中心法: 把状态转移表存起来, 扫描时查表。

自动生成工具:

- Lex/Flex: 根据正规式生成词法分析器。
- Yacc/Bison: 根据文法生成语法分析器。

Flex 文件一般分为声明、规则、辅助代码三部分。规则部分形如:

```text
pattern    action
```

词法分析重点不是背工具语法, 而是理解“正规式 -> 自动机 -> token 流”。

## 3. 文法与语法分析基础

### 3.1 上下文无关文法

语法分析要判断 token 串是否符合语言的语法规则。程序语言语法通常用上下文无关文法 CFG 表示。

一个文法 G 可写成四元组:

```text
G = (VN, VT, P, S)
```

- `VN`: 非终结符集合, 如 Expr、Stmt。
- `VT`: 终结符集合, 即 token。
- `P`: 产生式集合。
- `S`: 开始符号。

产生式例子:

```text
E -> E + T | T
T -> T * F | F
F -> (E) | id
```

### 3.2 推导、句型、句子

从开始符号出发, 不断用产生式替换非终结符, 这个过程叫推导。

- 句型: 从开始符号推导出来的符号串, 可以含非终结符。
- 句子: 只含终结符的句型。
- 最左推导: 每次替换最左边非终结符。
- 最右推导: 每次替换最右边非终结符。

语法树反映推导结构。不同推导如果对应同一棵语法树, 本质结构一样；如果一个句子有两棵不同语法树, 文法就是二义的。

### 3.3 二义性

典型二义性来自表达式优先级和悬空 else。

表达式文法:

```text
E -> E + E | E * E | id
```

对 `id + id * id` 可产生不同语法树, 因而二义。解决方法是把优先级写进文法:

```text
E -> E + T | T
T -> T * F | F
F -> id | (E)
```

这样乘法比加法绑定更紧。

## 4. 自顶向下语法分析

### 4.1 基本思想

自顶向下分析从开始符号 S 出发, 试图推导出输入串。直觉上是“从大结构拆成小结构”。

递归下降分析器就是为每个非终结符写一个函数。比如:

```text
Expr()
Term()
Factor()
```

每个函数根据当前 token 选择相应产生式。

### 4.2 左递归问题

自顶向下分析不能直接处理左递归。

直接左递归:

```text
A -> A α | β
```

消除后:

```text
A  -> β A'
A' -> α A' | ε
```

例如:

```text
E -> E + T | T
```

改为:

```text
E  -> T E'
E' -> + T E' | ε
```

### 4.3 提取左公因子

如果两个候选式开头相同, 预测分析器无法只看一个 token 决定走哪条路。

```text
A -> αβ1 | αβ2
```

提取为:

```text
A  -> α A'
A' -> β1 | β2
```

### 4.4 FIRST 与 FOLLOW

LL(1) 分析最重要的是 FIRST/FOLLOW。

`FIRST(α)`: 从 α 推导出的串可能以哪些终结符开头。如果 α 能推出空串, FIRST 里含 ε。

`FOLLOW(A)`: 在某个句型中, 非终结符 A 后面可能紧跟哪些终结符。若 A 可能出现在句尾, FOLLOW(A) 含 `$`。

构造预测分析表时:

- 若 `A -> α`, 对每个 `a in FIRST(α)` 填 `M[A,a] = A -> α`。
- 若 `ε in FIRST(α)`, 对每个 `b in FOLLOW(A)` 填 `M[A,b] = A -> α`。

如果同一个表格位置出现多个产生式, 就不是 LL(1) 文法。

## 5. 自底向上语法分析

### 5.1 移进-规约

自底向上分析从输入串出发, 反向规约到开始符号。它像是在找“当前栈顶哪一段可以被某个产生式右部替换成左部”。

操作:

- shift 移进: 把输入符号压栈。
- reduce 规约: 把栈顶某段右部替换成左部。
- accept 接受: 成功。
- error 出错。

关键概念:

- 句柄 handle: 在当前右句型中, 下一步应该被规约的子串。
- 活前缀 viable prefix: 可能出现在移进规约栈中的前缀。

### 5.2 LR 分析总览

LR 的意思:

- L: 从左到右扫描输入。
- R: 构造最右推导的逆过程。

LR 分析能力通常强于 LL, 很适合自动生成语法分析器。

层次关系大致可理解为:

```text
LR(1) 最强, 状态最多
LALR(1) 接近 LR(1), 状态接近 SLR
SLR(1) 使用 FOLLOW 简化
LR(0) 最简单, 能力最弱
```

### 5.3 LR(0) 项目与闭包

LR 项目是在产生式右部加一个点, 表示已经识别到哪里。

```text
A -> α . β
```

如果点后面是非终结符 B, 就要把 B 的产生式加入闭包:

```text
B -> . γ
```

构造项目集族时用两个操作:

- closure(I): 求项目集闭包。
- goto(I, X): 项目集 I 读入符号 X 后转移到的新项目集。

### 5.4 SLR(1)、LR(1)、LALR(1)

LR(0) 规约时不看向前符号, 容易冲突。SLR(1) 对归约项目 `A -> α .` 只在 `FOLLOW(A)` 中填规约动作, 因而减少冲突。

LR(1) 项目带一个向前看符号:

```text
[A -> α . β, a]
```

它更精确, 但状态多。

LALR(1) 的思路是: 把 LR(1) 中“核心项目相同”的状态合并, 向前看符号取并集。这样表大小接近 SLR, 能力通常接近 LR(1)。Yacc/Bison 常用 LALR(1)。

### 5.5 冲突

常见冲突:

- 移进-规约冲突: 既可以 shift, 又可以 reduce。
- 规约-规约冲突: 多个产生式都可规约。

表达式优先级、结合性、悬空 else 都容易产生冲突。解决方法包括改写文法、声明优先级/结合性、使用更强分析方法。

## 6. 语义分析与语法制导翻译

### 6.1 语义分析解决什么

语法正确不代表程序有意义。例如:

```c
int x;
x();
```

语法上可能像函数调用, 但 x 是整数变量, 类型不对。

语义分析负责:

- 作用域检查: 变量是否声明、是否在作用域内。
- 类型检查: 运算符和操作数类型是否匹配。
- 符号表管理: 记录名字、类型、作用域、地址、参数等。
- 语义动作: 生成中间代码或为后续生成做准备。

### 6.2 属性文法

属性文法是在 CFG 上加属性和语义规则。属性可以理解成语法树节点携带的信息。

- 综合属性: 从子节点传到父节点。比如表达式的类型、值。
- 继承属性: 从父节点或兄弟节点传给子节点。比如声明语句中的类型传给变量列表。

语法制导定义 SDD 关注“属性如何定义”。语法制导翻译方案 SDT 把语义动作嵌入产生式, 关注“什么时候执行动作”。

### 6.3 符号表

符号表是编译器保存名字信息的数据结构。典型条目包括:

- 名字 name
- 类别 kind: 变量、函数、类型、常量
- 类型 type
- 作用域 scope
- 存储位置 offset/address
- 参数信息 parameter list

块结构语言中, 进入新作用域就开新符号表或新层；离开作用域就弹出。

## 7. 中间代码生成

### 7.1 为什么要 IR

中间代码 IR 介于源语言和目标机器之间。好处:

- 便于优化。
- 便于移植。
- 降低前端和后端耦合。
- 可以支持多源语言、多目标机器。

常见 IR:

- 语法树/抽象语法树 AST
- 后缀式
- DAG
- 三地址码
- 四元式、三元式、间接三元式

### 7.2 三地址码

三地址码每条语句最多包含三个地址:

```text
t1 = a * b
t2 = c + d
t3 = t1 + t2
```

四元式通常写作:

```text
(op, arg1, arg2, result)
```

例如:

```text
(+, a, b, t1)
```

### 7.3 表达式翻译

翻译表达式时, 通常给每个表达式节点一个属性 `place`, 表示结果存放位置。生成临时变量:

```text
E -> E1 + T
E.place = newtemp()
emit(+, E1.place, T.place, E.place)
```

### 7.4 布尔表达式与控制流

布尔表达式有两种翻译思路:

- 数值法: 先算出 true/false 值。
- 控制流法: 直接生成跳转, true 跳到真出口, false 跳到假出口。

控制语句常见模板:

`if E then S`:

```text
E.code
ifFalse E.place goto L_after
S.code
L_after:
```

`while E do S`:

```text
L_begin:
E.code
ifFalse E.place goto L_after
S.code
goto L_begin
L_after:
```

`do S while E`:

```text
L_begin:
S.code
E.code
ifTrue E.place goto L_begin
```

这类题常考: 给语句写语法制导定义/翻译方案, 或手写四元式。

## 8. 运行时系统

### 8.1 名字绑定与存储分配

程序里的名字最终要绑定到存储位置。

常见绑定时间:

- 编译时: 静态分配。
- 运行时: 栈分配或堆分配。

三类存储区:

- 静态区: 全局变量、静态变量, 生命周期长。
- 栈区: 活动记录 activation record, 用于函数调用。
- 堆区: 动态分配对象, 生命周期更自由。

### 8.2 活动记录

一次过程调用对应一次活动 activation。活动记录通常包含:

- 返回地址
- 控制链 dynamic link
- 访问链 static link, 用于嵌套作用域
- 实参
- 局部变量
- 临时变量
- 保存寄存器

递归必须用栈分配, 因为同一个过程可能有多次未结束的活动。

### 8.3 垃圾收集

堆对象分配自由, 但回收困难。常见 GC:

- 引用计数: 每个对象记录引用数, 为 0 就回收。缺点是处理不了循环引用。
- 标记-清扫: 从根集合出发标记可达对象, 再清扫不可达对象。缺点是可能产生碎片。
- 复制收集: 把活对象复制到另一区域, 回收整个旧区域。好处是整理碎片, 缺点是需要额外空间。
- 分代收集: 基于“大多数对象很快死亡”的经验, 年轻代频繁收集, 老年代较少收集。

## 9. 代码优化

### 9.1 优化目标

优化不是改变程序语义, 而是在保持语义等价的前提下改进:

- 运行时间
- 存储空间
- 能耗
- 代码大小

优化分类:

- 局部优化: 基本块内部。
- 全局优化: 多个基本块。
- 循环优化: 针对循环, 最有价值。
- 机器无关优化与机器相关优化。

### 9.2 基本块与控制流图

基本块是只有一个入口、一个出口的连续语句序列。划分方法:

1. 第一条语句是入口。
2. 跳转目标是入口。
3. 跳转语句的下一条是入口。
4. 每个入口到下一个入口前构成一个基本块。

控制流图 CFG:

- 节点是基本块。
- 边表示控制可能从一个块流向另一个块。

### 9.3 DAG 局部优化

基本块内可构造 DAG 来发现:

- 公共子表达式
- 无用赋值
- 常量折叠
- 代数化简

例如:

```text
t1 = a + b
t2 = a + b
c = t2
```

可优化为:

```text
t1 = a + b
c = t1
```

### 9.4 数据流分析

数据流分析是在 CFG 上求程序性质。

典型问题:

- 到达定值 reaching definitions: 某个赋值是否可能到达某点。
- 活跃变量 live variables: 某变量的当前值以后是否还会被使用。
- 可用表达式 available expressions: 某表达式是否已算过且操作数未变。

解题套路是写出 GEN/KILL 集合和 IN/OUT 方程, 然后迭代到不变。

### 9.5 循环优化

循环执行次数多, 是优化收益最大的地方。

常见技术:

- 循环不变代码外提: 循环里每次结果都一样的表达式提到循环外。
- 强度削弱: 用便宜运算替代昂贵运算, 如乘法变加法。
- 删除归纳变量: 如果两个变量线性相关, 删除其中一个。
- 循环展开: 减少循环控制开销, 但会增大代码。

识别循环常用支配关系和回边。若 `d` 支配 `n`, 且存在边 `n -> d`, 这条边是回边, 对应一个自然循环。

## 10. 目标代码生成

### 10.1 三个核心问题

目标代码生成主要考虑:

- 指令选择: 用哪些机器指令实现 IR。
- 寄存器分配: 哪些变量放寄存器, 哪些溢出到内存。
- 指令调度: 调整指令顺序以减少等待, 同时保持依赖关系。

### 10.2 寄存器分配

寄存器比内存快, 但数量有限。

常见方法:

- 线性扫描: 按变量活跃区间扫描分配, 快, 适合 JIT。
- 图着色: 把变量冲突图染色。相互冲突的变量不能用同一寄存器。

如果寄存器不够, 需要 spilling, 即把某些变量放到内存。选择 spill 变量时可考虑:

- 冲突多的变量。
- 定义和使用少的变量。
- 尽量避免循环内频繁使用的变量。

## 11. 高频考点清单

- 写正规式, 构造或识别 DFA/NFA。
- 求 FIRST/FOLLOW, 构造 LL(1) 预测分析表。
- 消除左递归, 提取左公因子。
- 判断文法二义性, 写表达式优先级文法。
- 构造 LR(0)/SLR/LR(1)/LALR 项目集和分析表, 判断冲突。
- 说明 LR(0)、SLR、LR(1)、LALR 的差别。
- 写语法制导定义或翻译方案。
- 生成三地址码/四元式, 尤其是 if/while/do-while/布尔表达式。
- 符号表、作用域、类型检查。
- 活动记录、静态分配、栈分配、堆分配、GC。
- 划分基本块, 构造 CFG。
- DAG 局部优化, 数据流分析, 循环优化。
- 目标代码生成中的寄存器分配和 spilling。

## 12. 复习建议

编译原理不要只背定义。最好的复习方法是“每章至少会做一个手算题”:

- 词法: 正规式和自动机。
- 语法: FIRST/FOLLOW、LL(1)、LR 项目集。
- 语义/IR: 写语义动作和四元式。
- 优化: 基本块、CFG、DAG、数据流。
- 后端: 活跃变量、寄存器冲突和 spill。

如果只能抓主线, 就牢牢记住: 编译器每一阶段都在把程序换成更容易处理的表示, 同时尽量保留语义。
